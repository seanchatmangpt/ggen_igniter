## How to read the Evidence column

Each row's Evidence cell **is** the whole citation: a `file:line` reference, a
real command and its real output, or a link to the specialist doc that carries
both. There is no separate findings index behind this page.

A prior revision of this header instead sourced the whole page from a single
per-claim findings index at a top-level dot-directory, and repeated that
citation under See also. That path stopped resolving on 2026-09-01, when the
directory was archived (`docs/archive/README.md`); this header was never
updated to follow the move, so the one citation the page's authority rested on
had been unopenable for any reader since. Two corrections, both real:

- The file itself is not lost. It is
  `docs/archive/ggen_igniter_factory/docs-findings.jsonl` — 118 JSONL records
  (`claim`/`standing`/`evidence`/`documentation`/`follow_up`) from 10 distinct
  `agent` values, re-counted from the file itself rather than restated.
- The old header's own count was wrong: it advertised "93 individually-verified
  claims", against a real 118 records.

That file is **provenance, not current authority**. It is a 2026-08-27 snapshot
pinned to an in-flight HEAD (`767bcce`), and rows below have been re-verified
and superseded since — several findings it records as live defects are fixed
and cited as such here. Read it to see where a claim came from, never to
adjudicate what is true today.

**A row whose Evidence cell cites nothing resolvable is UNVERIFIED by
definition**, whatever status word sits next to it — and a citation that
silently stopped resolving, as this header's own did, is the same failure. That
is the standard `test/fixtures/ash_manufacture_pack/bin/evidence_check.py`
enforces for ontology citations; nothing enforces it mechanically for this
page, so it is stated here as a reading rule rather than claimed as a checked
property.

See `docs/glossary.md` for term definitions.

Status vocabulary used below (matching the vocabulary used consistently
across every specialist doc in this tree — not a separate scheme invented
for this page):

- **IMPLEMENTED** — real, currently working code, verified by direct reading
  and/or a real passing test run.
- **PARTIAL_ALIVE** — real and working, but with a disclosed, real gap or
  scope limit (not a stub).
- **PLANNED** — described in source (a moduledoc, a comment) as future work,
  not present in `lib/` today.
- **UNVERIFIED (this pass)** — the mechanism is real by inspection, but a
  full end-to-end run was not freshly executed and observed passing in this
  documentation pass (distinct from PLANNED — the code exists).
- **UNVERIFIABLE** — the code that would implement this capability has not
  landed in this working tree (the calling module compiles against it, but
  the target module/function genuinely does not exist on disk), so no run,
  passing or failing, can currently establish real status one way or the
  other. Distinct from PLANNED (no code references it yet) and from
  UNVERIFIED (the code exists; only a fresh run is missing).
