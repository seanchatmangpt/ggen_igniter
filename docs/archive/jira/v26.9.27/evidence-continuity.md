## How v26.10.1 manufacture receipts attribute fresh files

`EpochFreshness.check` reads `manifest.json` + `receipts/*.jsonl` (post-watermark, alive) + `HANDWRITTEN.md` rows dated ≥ watermark. The v26.10.1 flow is therefore: manufacture via the admitted generator (writes receipt + manifest) → `epoch.check` reads those fresh rows → ALIVE_GENERATED. No receipt, no attribution, no admission — the mechanism needs no data from the old epoch, only its own.

## Structural gap (open edge, recorded not solved)

Gitignored evidence dies with an epoch wipe unless exported, and a receipt inside the tree it certifies can never certify that tree's exact head (a commit cannot contain its own hash) — exact-head ALIVE needs **out-of-subject receipts** (git notes / OCI referrers / artifact store; composition catalog C21, standing UNKNOWN).

## Minimal boundary procedure (lawful today)

1. Before deleting any pre-epoch tree: `git notes add -f -R refs/notes/epoch/v26.9 --< archive` — or, minimally, `tar` `.ggen_igniter/` + qualification dirs onto a tagged archive ref (`epoch/v26.9-evidence`, commit-by-value).
2. Only then run the epoch wipe; the archive ref is the replay key.
3. v26.10.1 manufacture writes fresh receipts from run 1 — the new epoch's attribution never depends on the archive.
