## Detail

All items are static reading; nothing was run.

- F1/F2: `grep -n "Manifest\|on_stale\|on-stale" lib/ggen_igniter/reconcile.ex` gave no
  lines. `grep -n "Manifest\.\|stale_paths\|persist!" lib/mix/tasks/ggen_igniter.sync.ex`
  gave only line 362, a docstring. `reconcile.ex:17-33` says sync dispatches to
  `ReconcileReactor`.
- F3-F5: `manifest.md:163-166` says the default Sync path calls `Manifest.load/1`,
  `stale_paths/2`, `persist!/2` inline. `stale-artifacts.md:13` cites
  `manifest.ex:197-199` and its refuse section cites `sync.ex:665-667` and
  `Sync.resolve_on_stale!/1`. sync.ex 660-670 is `validate_contract_opts!`; the only
  `resolve_on_stale!` found is in the reactor.
- F6: `resolve_on_stale!/1` matches `nil` and three strings; `Reconcile.mode` accepts
  atoms (`reconcile.ex:179-187`). A keyword caller passing `:prune` would raise.
- F7: `all_new_paths` unions every recipe's `canonical_out_path`; old keys are
  re-canonicalized first. The docs show only the single-recipe formula.
- F9: prune runs in `finalize_evidence` after the `alive` receipt; failure is rescued
  and stored as `prune_failed` metadata, so callers may see `{:ok, receipt}` with
  stale files left.
- F11/F12: `prune!/1` sorts, then `File.rm/1` each; a non-enoent error raises after
  earlier deletions. Root containment is `ArtifactIdentity.within_root?` in
  admission (`reactor.ex:2033-2036`), not in `prune!/1`. A test titled for the
  partial-prune case exists at `test/ggen_igniter_reconcile_reactor_test.exs:657`;
  it was not run.
- F13: `recipe_key/2` is plain concatenation; no canonicalize call at that site.
- F16: `outputs` hashes are re-read from disk after write, so they baseline the
  generated bytes only.
- F17: `grep -n "on-stale\|on_stale" test/*.exs` per-file counts: destructive_change
  12, reconciliation_manifest 17, sync_inprocess_reconcile 11, reconcile_reactor 3.
  `preserve` has a test at `reconciliation_manifest_test.exs:252`. No atom-valued
  `on_stale` test or reactor `preserve_warning` text test was found by grep. Counts
  are greps, not results.
- F18: `Reconcile.run/1` is called in `semantic_jira_execute_test.exs:306-331` and
  `tera_wasm_test.exs:115`; those do not assert on manifest.json.
- F19: moduledoc `reconcile.ex:67` says `:engine` is ignored; code at 111-112 reads
  it and calls `Engine.fetch!/1`.
