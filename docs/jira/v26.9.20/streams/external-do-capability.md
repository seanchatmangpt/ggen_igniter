## Upstream gap record (ash_a2a 26.9.17)

Minimal repro, exactly as executed in F11:

```elixir
base = Igniter.Test.test_project(app_name: :semantic_jira)
# ash.gen.domain + ash.gen.resource SemanticJira.Work.Task ... --default-actions read,create,update
plain = Igniter.compose_task(base, "ash_a2a.install", ["--target", "SemanticJira.Work.Task"])
flagged = Igniter.compose_task(base, "ash_a2a.install",
  ["--target", "SemanticJira.Work.Task", "--skill", "update:update:external_do"])
# flagged.issues == [] and flagged.warnings == [] and the resource source is identical to plain:
#   a2a do
#   end
```

`AshA2A.Dsl` already accepts `skill :update, :update, consequence: :external_do`; the gap is
only that the installer cannot emit it, so an `external_do` capability has no default and stays
`:unknown` (refused, `:consequence_unclassified`) or a plain `:change` skill.

Proposed change to `ash_a2a.install`:

1. Add a repeatable option `skill: [:string, :keep]`, `--skill name:action[:consequence]`, with
   `consequence` one of `observe|change|external_do`, and reject an unknown value with an
   Igniter issue instead of dropping it.
2. Implement it with the same primitive this stream renders:
   `Igniter.Code.Function.move_to_function_call_in_current_scope(block, :skill, [2, 3], pred)`
   then `add_code` or `Igniter.Code.Keyword.set_keyword_key/4`.
3. Make `add_starter_dsl_block/2` idempotent. It calls `Igniter.Code.Common.add_code`
   unconditionally, so a second install appends a second `a2a do end` block; the manufacture
   template guards it with `skip_if_installed` and the F9 negative control pins it.

On merge and release, retire `@consequences`/`declare_consequences/3` from the template, pass
`--skill` in the `install_ash_a2a` step, and flip `gi:ash-a2a-consequence-override` to ALIVE.
