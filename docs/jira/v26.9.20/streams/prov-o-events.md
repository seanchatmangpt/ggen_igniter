## Design

- Per event: `<urn:ggen:sj:event:sha256:...>` a `prov:Activity` and `sj:StandingTransitionEvent`
  with `prov:used` of three `prov:Entity` nodes whose IRIs embed `definition_digest`,
  `snapshot_digest` and `receipt_digest` and whose `dcterms:identifier` repeats them; a
  `sj:StandingState` entity `prov:wasGeneratedBy` the event, `prov:wasDerivedFrom` the receipt,
  `prov:wasAttributedTo` `<urn:ggen:sj:authority:NONE>`.
- Log order is `sj:seq` (typed integer) plus a `prov:wasInformedBy` chain to the previous event.
- Any field outside the typed set (or with a non-conforming value) rides in one `sj:extra` JSON
  literal, so replay equals the log for arbitrary JSON-shaped events.
- Runtime-only assets live outside `gates/` and `templates/`: `runtime-queries/*.rq` and
  `runtime-templates/transition_log.ttl.eex`.

## Decisions and quarantined edges

- Gate under `gates/` NOT added (BLOCKED by an exact assertion, not by capability):
  `test/ggen_igniter_semantic_jira_pack_test.exs:864` asserts `length(gates) == 12`, and pack
  health / that suite execute every `gates/*.rq` against the work-order ontology (the event queries
  target an event graph). The queries are therefore runtime-only under `runtime-queries/`.
  Pack health and the pack suite are unaffected (verified, see receipt).
- Mix task NOT added: `test/ggen_igniter_cli_tasks_quirks_test.exs` is parametrized over every CLI
  task and `docs/reference/cli/` requires per-flag docs; the requested alternative
  (`TransitionLog.export_turtle/1`) is delivered instead.
- `prov:startedAtTime`: events from `Reconciler` carry no wall-clock time (adding one would change
  `event_digest` and break idempotent replay), so it is emitted only when an event supplies
  `started_at`.

## Findings about pre-existing behavior (not changed here)

- `SemanticJira.digest/1` drops top-level `receipt_digest` and `transition_digest`
  (`drop_digest_fields/1`), so `event_digest` does not cover them; `Provenance` covers them with the
  IRI cross-check and `sj:contentSeal`.
- `transition_digest` is identical across sibling transitions with the same `from`/`to`/`checks`
  (it excludes `work_order_digest`), so it is not a per-work-order identifier.

## Not claimed

Tamper evidence, not tamper proof: digests are unkeyed (ADR-010 "no signing"). A coordinated rewrite
that also recomputes `sj:contentSeal` (and `event_digest` for fields it covers) is undetected, and
truncating the tail of the log is undetectable from the Turtle alone.
