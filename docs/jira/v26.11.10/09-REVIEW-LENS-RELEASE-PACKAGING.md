# Expert Review — Release Packaging Lens (Hex & Ecosystem Distribution)

Comprehensive evaluation of package manifest hygiene, the Ash-free packaging fence, native build
artifact exclusion, and Hex.pm publication readiness for `ggen_igniter` v26.11.10.

- **Review Date:** 2026-11-10
- **Target Release:** `ggen_igniter` v26.11.10 (`1a6e60d6fed9c2adb06a2c097bbc83e8529f007e`)
- **Review Persona:** Meticulous Release Packaging Engineer.
  Dedicated to Hex.pm distribution hygiene, tarball minimization, strict dependency declarations,
  preventing platform-specific compiled binary leaks, and enforcing packaging isolation fences.

---

## Executive Summary & Stance

> "A published package on Hex.pm is permanent. Once pushed, it cannot be edited, only retired.
> If you leak an uncompiled debug file, a platform-specific `.so` dynamic library, or an
> unapproved internal experimental pack into the tarball, that flaw is etched into the ecosystem
> forever. Packaging must be verified against the real unpacked tarball before release."

This review evaluated `ggen_igniter` v26.11.10 by inspecting the actual tarball generated by
`mix hex.build --unpack`. The packaging receives an **APPROVED** verdict. The selective inclusion
rules in `mix.exs`, the enforcement of the Ash-free packaging fence via `shipped_packs/0`, and the
clean exclusion of compiled native binaries guarantee a production-grade distribution on Hex.pm.

## Section 1 — CONFIRMED Findings (Ranked)

### Blockers (Resolved)

#### B1. Prohibition of platform-specific compiled binaries in the Hex package
- **Observation:** If `priv` is included wholesale in `package[:files]`, compiled dynamic libraries (such as `priv/native/ggen_graph_nif.so` or `libggen_graph_nif.dylib`) would be packed into the Hex tarball. Because Hex packages are distributed to Linux, macOS, and Windows users across x86_64 and aarch64 architectures, shipping an OS-specific binary breaks consumer builds.
- **Packaging Engineer Assessment:** Hex packages utilizing Rustler NIFs must ship Rust source code (`native/ggen_graph_nif/Cargo.toml`, `Cargo.lock`, `src/`) and let Mix/Rustler compile the NIF during consumer installation.
- **Resolution in ggen_igniter:** `mix.exs:143-150` explicitly enumerates package contents rather than bundling bare `priv/`:
  ```elixir
  # mix.exs:143-150
  files:
    ~w(
      lib
      native/ggen_graph_nif/Cargo.toml
      native/ggen_graph_nif/Cargo.lock
      native/ggen_graph_nif/src
      priv/bundles
      priv/schema
      priv/graphlaw_wasm.wasm
      wasm-artifacts/tera_wasm_renderer.wasm
      mix.exs
      README.md
      LICENSE
      CHANGELOG.md
      usage-rules.md
      .formatter.exs
    ) ++ shipped_packs()
  ```
- **Result:** Real tarball unpack ([evidence/hex_package_manifest.txt](evidence/hex_package_manifest.txt)) confirms that `priv/native/` is completely absent from the Hex package.

#### B2. The Ash-Free packaging fence (`shipped_packs/0`)
- **Observation:** In accordance with operator directives, internal experimental Ash packs must not ship with the public package. The only admitted Ash pack is the qualified `ash-manufacture-pack`.
- **Resolution in ggen_igniter:** `mix.exs:163-171` implements `shipped_packs/0`:
  ```elixir
  defp shipped_packs do
    "priv/ggen"
    |> File.ls!()
    |> Enum.reject(fn pack_name ->
      # Exclude all ash* packs except the qualified ash-manufacture-pack
      String.starts_with?(pack_name, "ash") and pack_name != "ash-manufacture-pack"
    end)
    |> Enum.map(&Path.join("priv/ggen", &1))
  end
  ```
- **Verification:** Verified by `test/ggen_igniter_package_ash_free_test.exs`:
  - `hex_metadata.config` requirements contain zero `ash*` dependencies.
  - The only directory in `priv/ggen/` named for Ash is `ash-manufacture-pack`.
  - No shipped `lib/` module contains `use Ash.*`.

## Section 2 — REFUTED Findings

### R1. Refuted Claim: "WASM artifacts must not be shipped in Hex packages"
- **Claim:** Pre-compiled `.wasm` binaries should be excluded and downloaded at runtime.
- **Investigation:** Downloading binary assets at runtime creates fragile network dependencies and breaks offline or air-gapped builds. WebAssembly is architecture-independent bytecode that runs identically across macOS, Linux, and Windows.
- **Verdict:** REFUTED. Shipping deterministic WASM files (`priv/graphlaw_wasm.wasm`, `tera_wasm_renderer.wasm`) is standard best practice.
