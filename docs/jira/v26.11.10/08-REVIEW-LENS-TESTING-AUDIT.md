## Section 1 — CONFIRMED Findings (Ranked)

### Blockers (Resolved)

#### B1. Fleet receipt schema drift and silent test invalidation
- **Observation:** `priv/schema/fleet-receipt.v2.json` and its checksum `priv/schema/fleet-receipt.v2.sha256` had drifted from the authoritative machine fleet receipt schema at `~/.claude/dfcm/receipt.schema.json`.
- **Auditor Assessment:** When a schema file drifts from the fleet standard, receipts generated by the project cannot be validated across the multi-repository fleet, violating the Chatman Equation ($R = \text{receipt}(A)$).
- **Resolution in ggen_igniter:** Worker M1 re-vendored `priv/schema/fleet-receipt.v2.json` directly from `~/.claude/dfcm/receipt.schema.json` and updated `priv/schema/fleet-receipt.v2.sha256` to sha256 digest `a2c7510b91e59410ae46415a5f95f9cf3913a5c0ac42f473fcb6c794edfe4def`.
- **Verification:** `test/ggen_igniter_fleet_receipt_conformance_test.exs` asserts byte-for-byte identity and digest match: 10/10 tests pass cleanly.

---

### Majors

#### M1. Anti-vacuity mutation testing on security and agent guard hooks
- **Observation:** Many security hooks exist only as dormant scripts that are never tested against real attack vectors, failing open when invoked by agent runtimes.
- **Auditor Assessment:** A guard hook with no witnessed rejection carries zero bits of safety.
- **Validation in ggen_igniter:**
  - `.claude/hooks/refuse-handwritten-ash.sh` is tested by `test/ggen_igniter_agent_guard_test.exs` across 25 real-subprocess test cases.
  - The test feeds real JSON payloads via stdin matching the Claude/Gemini tool protocol.
  - It explicitly tests and verifies rejection (exit code 2) for:
    - Raw `use Ash.Resource`
    - Multiline continuation (`use Ash.` + newline + `Resource`)
    - Parenthesized macro calls (`use(Ash.Resource)`)
    - Combined base headers (`domain: SomeModule` and `otp_app: :app`)
    - Malformed JSON payloads (fails closed)
  - It proves that allowlisted templates and mix tasks exit 0.

#### M2. Chicago-style real packaging verification vs. mock doubles
- **Observation:** Unit tests that mock out package managers or file trees fail to catch real packaging defects (e.g. including forbidden files or corrupted tarball archives).
- **Validation in ggen_igniter:** `test/ggen_igniter_package_ash_free_test.exs` adopts strict Chicago-style testing:
  - Executes a real `mix hex.build --unpack` subprocess into a unique OS temporary directory.
  - Parses the real unpacked `hex_metadata.config` using `:file.consult/1`.
  - Scans every single regular file in the unpacked tree to verify that no forbidden `ash-*` packs or compiled native `.so` files were bundled.
  - Asserts that no shipped module uses `use Ash.*` via AST parsing.

#### M3. Mechanical documentation citation verification
- **Observation:** Release documentation frequently suffers from citation drift—referencing files, test logs, or receipts that were renamed or deleted during refactoring.
- **Validation in ggen_igniter:** The executable script `docs/jira/v26.11.10/bin/check_doc_citations.sh` greps all markdown files in `docs/jira/v26.11.10/` and mechanically verifies that 100% of cited paths, evidence files, and cross-referenced tickets resolve on disk. It exits with code 1 upon encountering any broken reference.
