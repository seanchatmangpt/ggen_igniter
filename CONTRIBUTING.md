# Contributing to ggen_igniter

This page takes you from a fresh clone to a green fast lane to a pull request. Deeper
material lives in `docs/contributing/`; toolchain and failure triage are in
[dev-setup](docs/contributing/dev-setup.md).

## 1. Get a green fast lane

Toolchain pins are in `.tool-versions` (Elixir 1.18.4 / OTP 27.2.4) and a working Rust
`cargo` toolchain is required, because compiling the library builds the
`native/ggen_graph_nif` Rustler NIF.

```bash
git clone https://github.com/seanchatmangpt/ggen_igniter.git
cd ggen_igniter
mix deps.get
mix ggen_igniter.doctor          # run first when anything looks wrong
mix compile --warnings-as-errors
mix format --check-formatted
mix test                         # fast lane: :integration tests excluded
```

The first compile builds the NIF and is slow; later builds are incremental. `mix test`
is the fast lane. The full suite is `GGEN_TEST_FULL=1 mix test` (or `mix test.full`);
CI runs it sharded. Measured times and the reasons are in
[dev-setup](docs/contributing/dev-setup.md).

## 2. Make a change

- Work on a branch; keep the diff small and coherent.
- Add or update tests with the change (see the non-negotiables below).
- Any new or changed CLI flag or task is documented in `docs/reference/cli/` in the same
  change.
- Add a `CHANGELOG.md` entry under the topmost version heading.

Guides for the common kinds of change:

- [Adding a pack](docs/contributing/adding-a-pack.md)
- [Adding a Reactor step](docs/contributing/adding-a-reactor-step.md)
- [Architecture rules](docs/contributing/architecture-rules.md) (the four hard invariants)
- [Testing](docs/contributing/testing.md)

## 3. Non-negotiables

1. **Chicago-style tests only.** Use real files, real subprocesses, real engines and
   state-based assertions. No `Mox`, `Mimic`, `Patch`, `:meck`, `mockall` or hand-rolled
   interaction mocks. Every test file starts with an `@moduledoc "Chicago-style: ..."`
   naming its real collaborators. This must exit 1 with no output before you push:

   ```bash
   grep -rn --include='*.ex' --include='*.exs' --include='*.rs' --include='*.py' \
     --exclude-dir=_build --exclude-dir=deps \
     -E '(use|import) +(Mox|Mimic|Patch)\b|(Mox|Mimic|Patch)\.|:meck\.|mockall|MagicMock|Mock\(' \
     test lib native
   ```

2. **Generated files are regenerated, not hand-edited.** A file carrying a
   `GENERATED by ggen_igniter from <pack>` header (for example
   `lib/mix/tasks/ggen_igniter.rename.ex`) is edited by changing its pack under
   `priv/ggen/<pack>/` and re-running `mix ggen_igniter.sync`. Hand-written library code
   is the exception and needs a row in `HANDWRITTEN.md` (format is in that file).
3. **Never hand-write Ash surfaces** (`use Ash.Resource`, `use Ash.Domain`). Model them
   in a pack and generate them. The package itself stays Ash-free.
4. **Mix tasks** are `use Igniter.Mix.Task` and handle `--help` through
   `GgenIgniter.TaskShell.run_with_help`.
5. **Versions are CalVer** (`vYY.M.D` style, currently `26.9.29`). `mix.exs` `version:`
   must match the topmost `CHANGELOG.md` heading; `mix ggen_igniter.doctor` checks it.
   Release bumps are made by the maintainer.
6. **Commit messages:** write the message to a file and run `git commit -F <file>`
   rather than passing multi-line text with `-m`.
7. **History is merge-only.** Do not rebase and do not force-push; integrate with merge
   commits.

## 4. Open the pull request

Before you open it, from the repository root:

```bash
mix compile --warnings-as-errors
mix format --check-formatted
mix test
```

The PR template has the checklist. CI (`.github/workflows/ci.yml`) additionally runs
`mix credo` and the sharded full suite.

## Reporting problems

- Bugs and feature ideas: open an issue using the templates.
- Security issues: do not open a public issue; see [SECURITY.md](SECURITY.md).
- Conduct: see [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
